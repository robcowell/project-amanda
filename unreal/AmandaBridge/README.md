# Amanda Bridge

An Unreal plugin that receives Project Amanda **protocol v1** over a local
WebSocket and broadcasts it to Blueprints.

This is the one place the build plan's "Blueprint first, C++ only where
justified" rule points at C++: the engine ships a `WebSockets` module with an
`IWebSocket` interface, but exposes **no Blueprint nodes for it**. Everything
above the socket stays in Blueprints.

> ⚠️ **This has never been compiled.** It was written on a Linux laptop with no
> Unreal install. See [Status](#status) before you spend an evening on it.

## Install

Copy or symlink the `AmandaBridge` folder into your project:

```
<YourProject>/Plugins/AmandaBridge/
```

Then regenerate project files (right-click the `.uproject` → *Generate Visual
Studio project files*) and build. The plugin is `EnabledByDefault`, so there is
nothing to tick in the plugin browser.

It needs a **C++ project**. A Blueprint-only project has no build pipeline to
compile the plugin with — which is why evening 1 of the build plan says to
create the project as C++ even though you will barely write any.

## Use

In any Blueprint's `BeginPlay`:

```
Get Game Instance Subsystem (Amanda Bridge Subsystem)
  └─ Bind Event to On Performance Update
  └─ Bind Event to On Gaze Set Target
  └─ Bind Event to On Speech
  └─ Bind Event to On Avatar Reset
```

It connects to `ws://127.0.0.1:8765` on game-instance start and reconnects for
as long as the game runs, so the orchestrator can be restarted freely. Override
with `Connect(Host, Port)`, or set `bAutoConnect` false and connect yourself.

### The events

| Event | Carries | Note |
|---|---|---|
| `On Bridge Connected` / `On Bridge Disconnected` | — / reason | Reconnection is normal, not an error |
| `On Session Started` / `On Session Ended` | `FAmandaSession` | |
| `On User Presence` | `bool` | False means walked away |
| `On User Speech` | `bool`, duration ms | Duration only meaningful when false |
| `On Thinking` | `bool` | Reduce eye contact, still the head |
| `On Speech` | phase, `FAmandaSpeech` | All four phases; switch on phase |
| `On Performance Update` | `FAmandaPerformanceUpdate` | Preset + intensity is the whole contract |
| `On Gaze Set Target` | `FAmandaGaze` | `HoldMs` is **advisory** — you own the timing |
| `On Gesture Trigger` | `FAmandaGesture` | Phase 6; on the wire from v1 |
| `On Avatar Reset` | — | Drop performance state, settle to neutral |
| `On Unknown Event` | name | Diagnostics only. Ignoring these is correct |

Two things worth internalising before you wire anything:

- **`speech.started` carries no audio and never will.** Audio reaches Unreal by
  a completely separate route (a virtual audio cable into a MetaHuman Audio Live
  Link source). These events are cues about audio that is arriving elsewhere,
  which is exactly why `speech.prepare` fires a beat earlier — it is your signal
  to return the gaze to the user *before* the first sample plays.
- **`On Avatar Reset` fires on every connection**, followed by the current
  session, performance and gaze. That is the orchestrator resynchronising you,
  so you never have to remember anything across a drop.

## Verify

Two steps, in order.

**1. Run the conformance tests.** *Tools → Session Frontend → Automation*,
filter for `Amanda`, run. Or headless:

```
UnrealEditor-Cmd.exe <Project>.uproject -ExecCmds="Automation RunTests Amanda; Quit" -unattended -nopause
```

Four suites cover the envelope, forward compatibility, payload validation, and
the full sample session. The sample-session fixture is **generated by the Python
reference implementation** (`Private/Tests/AmandaSampleSession.inl`), so this
decoder is tested against the exact bytes the orchestrator sends rather than a
hand-typed approximation. Regenerate it after any protocol change:

```sh
cd avatar-orchestrator && python3 tools/regenerate_unreal_fixture.py
```

**2. Talk to the real orchestrator.** On the machine running Unreal:

```sh
python3 tools/serve_sample_session.py --loop --speed 2
```

Press Play. The output log should show `bridge connected` and then 39 events per
loop. Stop and restart the Python side mid-replay — the bridge should reconnect
and receive a fresh `avatar.reset` without you touching anything.

## Status

**Written, not compiled.** There is no Unreal install on the machine this was
authored on, so every line is written against documented APIs and the protocol
semantics are verified only on the Python side.

What is genuinely verified:

- The protocol semantics, by 108 Python tests over the same rules.
- The fixture, which is generated rather than transcribed.
- That the sample session exercises all fifteen events.

What is not:

- That any of it compiles.

Three places most likely to need a nudge, in order of likelihood:

1. **`EAutomationTestFlags` in `AmandaBridgeTests.cpp`.** These constants moved
   out of the enum's scope in UE 5.5. There is a version shim at the top of the
   file; if it guesses wrong, the fix is one line and the compiler will say so.
2. **`FJsonObject::TryGetObjectField`** in `Decode`. The out-parameter is taken
   as `const TSharedPtr<FJsonObject>*&`, which is unusual enough to be worth
   checking against your engine version's header.
3. **Thread affinity of `IWebSocket` callbacks.** The engine delivers them on
   the game thread, so `HandleMessage` is normally a straight call. The hop
   through `AsyncTask` is defensive, because these are Blueprint-assignable
   delegates and broadcasting one off the game thread fails in ways that are
   very hard to trace back here. If it turns out to be unnecessary it costs one
   branch.

## Design notes

**Why a `UGameInstanceSubsystem`.** It survives level changes, there is exactly
one, and its lifetime brackets PIE cleanly. An Actor would need placing in a
level and would take the connection down on every travel.

**Why the protocol layer is separate.** `FAmandaProtocol` touches no engine
state, no socket and no `UObject`, so the automation tests exercise it directly.
This mirrors the Python split, where `protocol.py` knows nothing about
`websocket.py`.

**Why this side is lenient and Python is strict.** The Python implementation
rejects an out-of-range coefficient because it is the *producer* — a director
emitting `1.4` has a bug, and failing loudly at the source is how it gets fixed.
This is the *consumer*, where refusing a message only means the avatar misses a
direction and nobody learns anything. So here: unknown events are skipped,
unknown fields ignored, unknown enums fall back, out-of-range floats are clamped
and logged. Missing *required* fields are still refused, because that is a
malformed message rather than a compatibility case.

**Why `bHas...` flags instead of optionals.** Blueprint has no `TOptional`, and
a defaulted `0.0` for an absent override is indistinguishable from a deliberate
`0.0`. The flags keep "not sent" and "sent as zero" apart, which matters because
an animation graph that only implements presets is supposed to ignore the
overrides entirely.
